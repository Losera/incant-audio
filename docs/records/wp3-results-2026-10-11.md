# WP3 results — the repair-loop headline is a visibility effect, not a faust-rs effect

Point-in-time record. Not maintained after today — see COLLABORATION.md §8. Reports the
run pre-registered in `bench/repair_ab_repro/WP3_PROTOCOL.md` (written 2026-09-24, before
any arm ran). Data: `bench/results/repair_ab/wp3_20261009.json` (960 records, 192 screened
programs × 5 arms, `qwen2.5-coder:3b`, local ollama). Scoring:
`bench/repair_ab_repro/score_wp3.py`.

## Headline

**The original PF-076 finding — "faust-rs's diagnostics make the repair loop worse" — does
not survive a fair test of faust-rs's content alone.** Once the correction wrapper is
matched across arms and source-line visibility is held fixed, faust-rs's diagnostic
*content* (code, message, notes, help) shows **no significant effect** (B2n vs A2,
McNemar p = 0.545). What the original A/B actually measured was **source-line visibility**:
showing the model one caret-quoted line of its own broken program drops its repaired-within-2
rate from ~70% to ~40%, regardless of whether that line arrives via faust-rs's rich
diagnostic, faust-rs's minimal diagnostic, or (by construction) nothing in the C++ arm at
all.

## Numbers

| Arm | Content | Source shown | n | repaired-within-2 |
|---|---|---|--:|--:|
| A2 | raw C++ stderr | n/a (uncontrolled leak, see L14) | 192 | 134 (70%) |
| B2n | faust-rs full | **no** | 192 | 128 (67%) |
| C2n | faust-rs minimal | **no** | 192 | 143 (74%) |
| B2 | faust-rs full | **yes** | 192 | 76 (40%) |
| C2 | faust-rs minimal | **yes** | 192 | 78 (41%) |

**Primary endpoints** (paired exact McNemar, `score_wp3.mcnemar_report`):

1. **B2n vs A2** (the fair content test) — n=192, discordant 37/31, **p = 0.545. Not
   significant.** faust-rs's diagnostic content, shown fairly (matched wrapper, no source
   splice), is indistinguishable from raw C++ stderr.
2. **B2 vs B2n** (visibility factor, full renderer) — n=192, discordant 63/11,
   **p = 5.32e-10.** Adding the source-line splice to the *same* faust-rs content collapses
   the repair rate from 67% to 40%.
3. **C2 vs C2n** (visibility factor, minimal renderer) — n=192, discordant 75/10,
   **p = 1.86e-13.** Same pattern, independent of faust-rs's prose/notes/help — it is not
   verbosity plus visibility, visibility alone does this.
4. **A (original, product wrapper) vs A2 (matched wrapper)** — sanity/determinism check,
   n=192, discordant 30/21, p = 0.262. **No wrapper-identity effect** — the original
   wrapper-mismatch (L3) was not itself driving anything; the pre-registered determinism
   stop-condition does not trigger.

**Decision rule applied** (stated in WP3_PROTOCOL.md before this run, not fit to it after):
*"B2n vs A2 is not significant, but B2 vs B2n shows a real effect"* →
**the original effect was substantially the visibility confound, not faust-rs's content per
se.** This is exactly the pattern that fired.

## What this resolves, and what it doesn't

**Resolves L3 (unmatched wrapper):** sanity check (4) shows wrapper identity isn't driving
anything once matched — ruled out as the mechanism.

**Resolves L12/L14 (visibility is not a controlled factor, arm A isn't clean zero-visibility
either):** WP3's design didn't need arm A to be a clean zero-visibility baseline (per
WP3_PROTOCOL.md's own design note — visibility was isolated entirely on the faust-rs side,
treating arm A's leak rate as a measured covariate, not a factor). The B2-vs-B2n and
C2-vs-C2n comparisons hold content fixed and vary only the deliberate source splice, which is
a clean controlled toggle regardless of what arm A's stderr happens to leak.

**Resolves L13/L15 (faust-rs's own repair-suggestion list is stripped):** moot for this
question — B2n/C2n already show faust-rs's content (stripped or not) isn't the driver, so
whether the stripped list would have helped is now a secondary question, not the explanation
for the original headline. Still open as its own question (B2r, exploratory, not part of this
factorial per WP3_PROTOCOL.md's own scope note) — restated below.

**Does not resolve / explicitly out of scope (per WP3_PROTOCOL.md):**
- Whether a frontier model shows the same pattern.
- Whether faust-rs's stable code as a *branch signal* (rather than pasting diagnostic text)
  would help — untested, and now a more interesting question than before, since content
  alone is inert here.
- B2r (faust-rs full, repair-suggestions kept) — deliberately excluded from this factorial to
  avoid confounding it (WP3_PROTOCOL.md, "Explicitly not run by this protocol"). Now that the
  real driver is known to be visibility, not content, B2r's marginal value is lower than it
  looked before this run — it would still only probe content, which this run already shows is
  inert on this corpus.
- The exploratory `leak_score` table (A2 stratified by error class) remains descriptive only,
  per the pre-registration — `leak_score` is ~deterministic given error class, so it cannot
  separate "visibility helps/hurts" from "this class is just easier/harder."
